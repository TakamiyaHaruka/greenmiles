# GreenMiles 开发流程记录

---

## 一、应用设计

**输入文档：**
- UI 设计初稿（配色方案、视觉风格、页面布局描述）
- 碳排放计算规范（三因子公式、机型系数、舱位权重）

**使用 BMad 方法论：**
- `bmad-product-brief` — 定义产品定位和核心价值
- `bmad-prd` — 多轮对话推导结构化需求，产出 19 条决策日志
- `bmad-create-ux-design` — 打磨交互细节（Sheet 抽屉、Dialog 弹窗、圆环图可视化）
- `bmad-party-mode` — 多 Agent 讨论产品简介的内容框架

**实现内容：**
- 产品定位：商城是主体，计算器是工具（Decision #13）
- 核心体验：Reveal → Offset → Proof 情感旅程
- 4 种商品类型覆盖 4 种兑换逻辑
- 碳排放公式：CO2(kg) = 距离 × 机型系数 × 舱位权重
- 交互规范：余额不足置灰+差额提示、商品详情 Sheet 抽屉、购物车 Dialog

**输出物：**
- Product Brief（产品简介）
- PRD（产品需求文档，含 19 条决策日志）
- UX Design Specification（UX 设计规范）

## 二、数据库设计

**输入文档：**
- PRD 中的功能需求（用户、商品、订单、碳排放记录）
- Architecture 文档中的技术约束

**使用 BMad 方法论：**
- `bmad-create-architecture` — 技术选型讨论，确定 SQLite + better-sqlite3

**实现内容：**
- 4 张表设计：
  - `users` — id, email, password_hash, miles_balance（默认 10,000）
  - `products` — id, name, description, category, mileage_cost, stock, icon_type
  - `orders` — id, user_id, product_id, status, voucher_code, address
  - `carbon_records` — id, user_id, distance, aircraft_type, cabin_class, co2_kg
- WAL 模式启用
- 种子数据：1 个测试用户 + 4 个商品

**输出物：**
- `src/lib/db.ts`（数据库连接 + 建表 + 种子数据）
- `greenmiles.db`（SQLite 数据库文件）

## 三、接口设计

**输入文档：**
- PRD 功能需求（用户认证、商品管理、订单管理）
- Architecture 文档中的 API 模式（统一返回格式 `{ data }` 或 `{ error }`）

**使用 BMad 方法论：**
- `bmad-create-architecture` — 确定 RESTful API 风格、JWT 认证方案
- `bmad-create-epics-and-stories` — 将 API 需求拆分到具体 Story

**实现内容：**

| 端点 | 方法 | 说明 |
|------|------|------|
| /api/auth/register | POST | 用户注册，Zod 校验，bcrypt 加密 |
| /api/auth/login | POST | 用户登录，JWT 生成，httpOnly cookie |
| /api/user | GET | 获取当前用户信息 |
| /api/products | GET | 商品列表 |
| /api/orders | POST | 创建订单（SQLite 事务：扣减余额 + 创建记录 + 减库存） |
| /api/orders | GET | 当前用户订单列表 |

**输出物：**
- 6 个 API Route 文件
- `src/lib/schemas.ts`（Zod 校验 schemas）
- `src/lib/auth.ts`（JWT 工具函数）
- `src/middleware.ts`（路由保护中间件）

## 四、开发计划

**输入文档：**
- Epics & Stories 文档（4 个 Epic、15 个 Story）
- Architecture 文档

**使用 BMad 方法论：**
- `bmad-check-implementation-readiness` — 检查 PRD/UX/Architecture/Epics 对齐
- `bmad-sprint-planning` — 生成 sprint-status.yaml 进度追踪文件

**实现内容：**
- 15 个 Story 的依赖关系和执行顺序
- Sprint 状态追踪机制（backlog → ready-for-dev → in-progress → done）

**输出物：**
- `sprint-status.yaml`（进度追踪文件）
- Implementation Readiness Report（就绪检查报告）

---

## 五、代码研发

**输入文档：**
- 15 个 Story 文件（每个含 BDD 格式 Acceptance Criteria、Tasks/Subtasks、Dev Notes）
- sprint-status.yaml

**使用 BMad 方法论：**
- `bmad-dev-story` — 按 Story 文件逐一实现代码

**实现内容：**

| Epic | Stories | 核心产出 |
|------|---------|----------|
| Epic 1: 基础设施 | 5 个 | 项目初始化、数据库、注册、登录、导航栏 |
| Epic 2: 碳排放计算 | 3 个 | 计算引擎、计算器 UI、上下文 Banner |
| Epic 3: 绿色商城 | 5 个 | 商品列表、详情 Sheet、购物车、结算、API |
| Epic 4: 会员控制台 | 2 个 | 订单历史、KPI 看板 |

**输出物：**
- 11 个组件文件（Navbar, CarbonCalculator, ProductCard, CartDialog 等）
- 6 个页面文件（首页, 登录, 注册, 计算器, 商城, 订单）
- 6 个 API Route 文件
- 3 个 Store 文件（userStore, carbonStore, cartStore）
- 5 个 Lib 文件（carbon, db, schemas, auth, utils）
- 15 个 Story 完成记录文件

---

**总结：** 5 个阶段串联起从需求到代码的完整链路，每个阶段的输出物是下一阶段的输入文档，形成闭环。
